# 개발 로드맵: 노션 기반 포트폴리오 · 경력관리 웹사이트

- 기준 문서: [`docs/PRD.md`](./PRD.md)
- 전체 예상 소요: 9~14일 (Phase 1~5 합산)
- 각 Phase는 이전 Phase의 산출물에 의존하므로 순서대로 진행한다.

| Phase | 내용 | 예상 소요 |
|---|---|---|
| 1 | 프로젝트 초기 설정 | 1-2일 |
| 2 | 공통 모듈 개발 | 2-3일 |
| 3 | 핵심 기능 개발 | 3-4일 |
| 4 | 추가 기능 개발 | 2-3일 |
| 5 | 최적화 및 배포 | 1-2일 |

## Phase 1: 프로젝트 초기 설정 (1-2일)

**이유**: 견고한 기반 없이는 이후 기능 개발이 어렵다. Notion 연동 자체가 실패하면 뒤 단계 전부가 막히므로 가장 먼저 검증한다.

**작업 항목**
- Next.js 프로젝트 구조 설정 (`src/app` 라우트 뼈대: `/`, `/projects/[id]` 생성, 레이아웃 파일 정리)
- Notion API 연동 환경 구축
  - Notion Integration 생성 및 API 키 발급 (PRD "사전 준비 사항" 체크리스트 참고)
  - 프로필/경력/프로젝트 3개 데이터베이스에 Integration 연결, DB ID 확보
  - `@notionhq/client` 설치, `.env.local`에 `NOTION_API_KEY`, `NOTION_PROFILE_DB_ID`, `NOTION_CAREER_DB_ID`, `NOTION_PROJECTS_DB_ID` 등록
  - 간단한 테스트 스크립트로 `databases.query` 1회 호출해 연결 확인
- 기본 레이아웃 구조 생성 (전역 헤더/푸터 자리, Tailwind/shadcn 설정 점검)

**완료 기준**
- [ ] `npm run dev`로 로컬 서버가 정상 구동된다
- [ ] 테스트 스크립트가 노션 3개 DB로부터 데이터를 실제로 받아온다 (인증/권한 오류 없음)
- [ ] 홈/`projects/[id]` 라우트 파일이 생성되어 있고 빈 페이지라도 렌더링된다
- [ ] `.env.local`이 `.gitignore`에 포함되어 있어 키가 커밋되지 않는다

## Phase 2: 공통 모듈 개발 (2-3일)

**이유**: 모든 화면에서 재사용되는 코드를 먼저 만들어야 Phase 3~4에서 중복 구현을 피할 수 있다.

**작업 항목**
- Notion API 공통 함수 (`src/lib/notion/`)
  - `fetchProfile()`, `fetchCareers()`, `fetchProjects()` — PRD 7번 "조회 방식" 기준으로 `공개여부: published` 필터 적용
  - `mapNotionPageToProfile / Career / Project` 매퍼 함수 — PRD 7번 데이터 모델의 TypeScript interface 및 매핑 예시 코드 기준
- 공통 컴포넌트 (`src/components/`)
  - `Header`, `Footer`
  - `Card`(프로젝트 카드), `Badge` 활용 스킬 태그, `Timeline`(경력 타임라인 아이템)
- 공통 타입 정의 (`src/types/portfolio.ts`)
  - `Profile`, `Career`, `Project`, `PublishStatus` — PRD 7번에 정의된 인터페이스 그대로 사용

**완료 기준**
- [ ] `fetchProfile/fetchCareers/fetchProjects`가 방어적 파싱(FR-7)을 포함해 정상 동작한다 (필드 누락 시 예외 없이 기본값 반환)
- [ ] `공개여부: draft`인 항목이 조회 결과에서 제외된다 (FR-6)
- [ ] `Header/Footer/Card/Badge/Timeline` 컴포넌트가 더미 데이터로 독립 렌더링 확인된다
- [ ] 공통 타입에 `any`가 없다

## Phase 3: 핵심 기능 개발 (3-4일)

**이유**: 핵심 기능은 Phase 2에서 만든 공통 모듈을 조립해 방문자가 실제로 사용하는 화면(PRD의 P0 요구사항)을 완성하는 단계다. 부가 기능보다 먼저 끝내야 MVP로서 의미가 있다.

**작업 항목** (PRD 5번 기능 요구사항 중 P0 항목 기준)
- 홈 페이지(`/`) 구현 — 프로필 히어로, 경력 타임라인, 프로젝트 그리드 (FR-3, PRD 8번 화면 설계)
- 프로젝트 상세 페이지(`/projects/[id]`) 구현 — 설명/역할/기술/링크, 존재하지 않거나 비공개 시 404 (FR-4)
- 이력서 PDF 다운로드 (`/api/resume/pdf`) — `@react-pdf/renderer` 템플릿 + 한글 폰트(Noto Sans KR) 등록 (FR-5, PRD "PDF 생성 및 다운로드")
- ISR 재생성 전략 적용 — 페이지/데이터 조회에 `revalidate` 설정, 방문 요청마다 Notion API 직접 호출하지 않도록 구성 (FR-9)
- 반응형 기본 대응 — 모바일에서 프로젝트 1열, 경력 세로형 (FR-8, 세부 다듬기는 Phase 5)

**완료 기준**
- [ ] 홈 페이지에서 노션에 입력한 프로필/경력/프로젝트가 실제로 보인다
- [ ] 프로젝트 상세 페이지 진입/뒤로가기가 정상 동작하고, 존재하지 않는 ID는 404를 반환한다
- [ ] "이력서 PDF 다운로드" 버튼으로 한글이 깨지지 않는 PDF가 다운로드된다
- [ ] 노션에서 값을 수정한 뒤 재생성 주기(또는 로컬 재빌드) 후 사이트에 반영된다
- [ ] 모바일 뷰포트(375px 기준)에서 레이아웃이 깨지지 않는다

## Phase 4: 추가 기능 개발 (2-3일)

**이유**: 핵심 기능이 완성된 후 부가 기능을 추가해야 우선순위가 뒤바뀌지 않는다.

> ※ 아래 "기술 스택 필터링"과 "검색 기능"은 PRD의 기능 요구사항(FR) 표에는 없는 항목입니다. PRD에 정의된 프로젝트 `skills`(multi_select) 필드를 활용해 자연스럽게 확장 가능한 기능으로 제안했으며, 실제로 진행할지는 확인이 필요합니다.

**작업 항목**
- SEO 최적화 — `generateMetadata`로 동적 title/description/OG 이미지, `sitemap.ts`, `robots.ts` (FR-10, P0이지만 개발 순서상 부가 기능 단계에 배치)
- 기술 스택(스킬) 필터링 — 프로젝트의 `skills` 태그 기준으로 목록 필터링 (PRD 미정의, 제안 기능)
- 검색 기능 — 프로젝트 제목/한줄소개 기준 클라이언트 사이드 텍스트 검색 (PRD 미정의, 제안 기능)
- 프로젝트 정렬 순서 적용 — 노션 `order` 필드 우선, 없으면 기간 최신순 폴백 (FR-12, P1)
- Notion API 429 재시도 로직 — 재생성 작업 실패 방지 (FR-11, P1)

**완료 기준**
- [ ] Lighthouse SEO 점수 90점 이상, `sitemap.xml`/`robots.txt`가 정상 응답된다
- [ ] (진행 확정 시) 기술 스택 필터/검색이 실제 데이터로 정상 동작한다
- [ ] `order` 필드가 있는 프로젝트가 지정한 순서대로, 없는 프로젝트는 최신순으로 표시된다
- [ ] 의도적으로 429를 유발해도 재생성 작업이 죽지 않고 재시도 후 성공한다

## Phase 5: 최적화 및 배포 (1-2일)

**이유**: 기능이 완성된 후 품질을 끌어올리는 단계로, PRD의 성공 지표(KPI)를 실제로 만족하는지 마지막으로 검증한다.

**작업 항목**
- 성능 최적화 — 이미지에 `next/image` 적용, 폰트 최적화(`next/font`), 불필요한 클라이언트 번들 축소 (KPI: LCP 2.5초 이내)
- 반응형 디자인 개선 — 실기기/여러 브레이크포인트 QA, Phase 3에서 남은 레이아웃 이슈 정리
- Vercel 배포 — 환경변수(Notion API 키, DB ID) 프로덕션 등록, 커스텀 도메인 연결 여부 확인, 배포 후 스모크 테스트

**완료 기준**
- [ ] Lighthouse Performance 점수 및 LCP가 PRD KPI(2.5초 이내) 기준을 만족한다
- [ ] 모바일/태블릿/데스크톱 3개 뷰포트에서 QA 체크리스트 통과
- [ ] 프로덕션 배포 URL에서 홈/프로젝트 상세/이력서 PDF 다운로드가 모두 정상 동작한다
- [ ] 프로덕션 환경변수에 `NOTION_API_KEY` 등이 노출 없이 정상 설정되어 있다

## 확인 필요 사항 (PRD와 연계)

- Phase 4의 "기술 스택 필터링"·"검색 기능" 진행 여부 — PRD 기능 요구사항에 없는 신규 제안이므로 범위 포함 여부 확정 필요.
- PRD "확인 필요 사항"(재생성 주기, 프로필 DB/페이지 방식, 커스텀 도메인 등)이 Phase 1~2 착수 전에 먼저 정리되어야 일정 지연이 없다.
